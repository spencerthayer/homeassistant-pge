## Learned User Preferences

- Prefer unattended Home Assistant operation via stored PGE email/password; no HITL bearer-token handoff and no MFA support (MFA accounts are unsupported). Treat portal access tokens as short-lived: re-login may be required nearly every sync interval, including mid-sync renewal. Respect Cognito password-login rate limits—back off instead of hammering InitiateAuth so accounts are not throttled or banned.
- Auth/sync failures must soft-fail: keep last-known sensors and recorder history; never blank the panel or purge downloaded usage/billing because renew failed. Long-running backfill must self-heal on stall (progress watchdog / stuck-task recovery) so sync_status cannot stay backfilling indefinitely without a HA restart.
- Prefer Cursor Browser (`cursor-ide-browser`) for live HA UAT with `./scripts/start.sh`/`./scripts/stop.sh`; reuse the existing live HA process—do not spawn a second/ad-hoc instance when one is already running. Custom-component Python changes need a full HA process restart (config-entry reload is not enough). After every substantive code or frontend change, confirm the affected surface (usually `/pge`) reflects the change and data loads correctly—blank, stale shells, or unexpected `unavailable` count as failure and require `./scripts/stop.sh` then `./scripts/start.sh` plus hard-refresh before calling the work done. Panel Sync status must reach complete (no failed backfill days) before UAT is done. Plans should embed Browser UAT checkpoints at code-review points (verify at `/config/integrations/integration/pge_energy`) and use the `.cursor/.ralph` loop for continuity, stopping only for HITL UAT confirmation before marking complete.
- Prefer the continual-delivery plan under `.cursor/plans/` as the source of truth (`instruct.md` is legacy); do not edit `.cursor/plans/` unless explicitly asked.
- Prefer polling interval UI as a number plus a minutes/hours/days dropdown (default every 4 hours) plus a configurable Pacific sync clock that anchors the hour/day grid (default 12:00 AM → 12am/4am/8am/noon/4pm/8pm), with no static “minutes” suffix on the number field.
- Prefer credentials-only setup (email/password + account number per entry); source naming includes the account number (e.g. `PGE <accountnum>`); locally bundled PGE logo; options UI with password reveal; account number read-only after setup. Same login may own multiple entries with different account numbers. Prefer no personal account details hardcoded outside `.env` (which is intended to be removed); never commit secrets.
- Prefer tiered full-history sync into HA (hourly, then daily/monthly as available), with user-controllable sync frequency and history depth in settings, plus a manual force-sync path: a start modal that reuses saved sync settings, then a dedicated progress page (not just a popup) with real-time stats, ETA, and a progress bar.
- Prefer stock Home Assistant Energy (`/energy`) and native energy cards for consumption, cost, and PGE outdoor temperature; do not depend on third-party energy chart addons.
- Prefer a first-party sidebar panel at `/pge` titled **PGE** as the single place for usage, billing, programs, and live sync — buildless ES module + vendored Apache ECharts only (no embedded HA `hui-energy-*` / `hui-statistics-graph-card` fallback shells on `/pge`); never `/energy/pge` (HA routes panels by the first path segment). Prefer Configure → Panel as domain-global chrome (Store `pge_energy.panel`, not per-account options): show/hide the sidebar link while keeping `/pge` reachable and Manual sync available, sidebar title (default `PGE`), MDI icon (default `mdi:transmission-tower`), admin-only, and default landing section (At a glance / Usage / Analytics / Billing). Never read/write frontend user-store `sidebar` / `panelOrder` / `hiddenPanels` (conflicts with Browser Mod); leave sidebar order to HA’s sidebar editor and/or Browser Mod. Panel/chart colors must follow HA theme tokens (light/dark/custom) so text and series stay readable when themes change.
- Prefer panel “At a glance” KPIs and Usage/analytics charts that respect PGE overnight publication lag (~24h): closed days through yesterday only — never wall-clock “today”, tip/latest-hour samples, tip outdoor temperature, or incomplete/open periods. Include “Since statement” cost/kWh (statement end → yesterday); chart ranges end at Pacific midnight exclusive; Usage primary fast-select is `24h` / This cycle / Last cycle / 7 days / Month, with More… for `6h`/`12h`/`3mo`/`6mo`/`12mo`/YTD (default `24h`; short windows are last N hours of published data); keep unavailable presets visible but disabled; put Sync status under At a glance in one collapsible with PGE publication gaps below sync (default collapsed; persist open/closed like Range accounting). Prefer a combined multi-series Usage chart with fuller bars; analytics layout is Weather vs usage full-width above side-by-side Cost intelligence, equal chart heights, and heatmap titles above the plot. Range accounting should scale with the selected window (including multi-year/decade histories) while keeping hourly detail available; hide metrics that are zero only from missing data; keep Range accounting and breakdown tables as separate collapsibles whose open/closed state persists across range changes and browser reloads (default collapsed); style Billing as always-expanded (no accordion) matching Range accounting table layout; omit a separate Table view control (redundant with Range accounting); keep the panel mobile/tablet friendly; charts should highlight both bars and line points on hover, with tasteful hover motion on graphs and KPI cards; chart tooltips/popups should show human-facing PGE values and readable dates (not internal calculated intermediates).
- Prefer billing/programs as structured dual-publish data on the same entry/device (sensors + binary sensors + mirrored statistics); bill PDF download is opt-in (`download_bill_pdfs`, default off) with automatic local parsing, fail-closed GraphQL reconciliation, separate binary retention vs normalized Store/recorder history, and distinct `_bill_pdf_*` statistics (GraphQL bill sensors remain canonical; PDF line-item sensors default-enabled when `download_bill_pdfs` is on so DIY Lovelace can use them, and stay disabled when the option is off—panel Statement details and `pge_energy:…_bill_pdf_*` statistics cover history). Prefer status/conditions for HA automations via a hybrid alert surface: typed `pge_energy_alert` domain events plus summary entities (problem/alert/reauth/failed-days/auth-fail-count), with HA repairs for critical/actionable issues; no built-in notify service—user automations own notifications. v1 catalog is core ops (auth/sync/billing/new bill) plus account lifecycle (amount-due/due-date, program/autopay flips), not data-quality signals.
- Prefer documenting important code changes in the matching docs (`docs/ARCHITECTURE.md`, `docs/AUTH_DISCOVERY.md`, `docs/DATA_CONTRACT.md`, `README.md`, `SECURITY.md` as applicable; see `.cursor/rules/document-and-track-tasks.mdc`). After substantive `custom_components/pge_energy` changes, complete the HACS upgrade cycle: bump SemVer (PATCH/MINOR/MAJOR), sync `const.py` / `manifest.json` / frontend `?v=` / README, commit + push on a named branch, wait for fully green CI on that SHA, then publish a matching GitHub Release (`vX.Y.Z` via `gh release create` as Latest) so HACS can offer the upgrade (see `.cursor/rules/bump-version-on-code-changes.mdc` and `.cursor/rules/hacs-release-requires-green-ci.mdc`). Never publish a HACS Latest from a commit that failed any required check; fix, push again, and advance SemVer if the broken tag was already published.

## Learned Workspace Facts

- This repo (`homeassistant-pge`) is a Home Assistant custom integration under `custom_components/pge_energy` (PGE Energy / Portland General Electric), prepped for public HACS distribution.
- Local live HA for browser UAT is started with `./scripts/start.sh` (via `scripts/dev_ha_live_server.py`) at `http://127.0.0.1:8123`; stop with `./scripts/stop.sh`; run dirs live under `outputs/ha_live/` (gitignored). On bare `./scripts/start.sh` HA (no Supervisor), `homeassistant.restart` from the UI can kill the process without bringing it back—use `./scripts/stop.sh` then `./scripts/start.sh`.
- In-process harness is `scripts/dev_ha_harness.py` with outputs under `outputs/ha_harness/`; `.env` loading is opt-in via `env_loader` and must never auto-load in tests/CI.
- Shell commands in this workspace should use `exec /bin/bash -lc '...'` to avoid zsh wrapper exit-code noise.
- Auth path is Cognito + Apigee hybrid email/password (`portal_auth`); MFA and captcha challenges fail closed as unsupported. Cognito InitiateAuth throttle (`TooManyRequestsException`) and password-attempt lockout (`NotAuthorizedException` / “Password attempts exceeded”) map to `PGERateLimitError` with a shared per-email cooldown; soft-fail polls without reauth and do not fall back password→refresh while cooling down.
- OptionsFlow exposes Configure → Sync settings, Update credentials, and Panel (domain Store `pge_energy.panel`); polling is `polling_interval` + `polling_interval_unit` + `sync_local_time` (default every 4 hours from 00:00 America/Los_Angeles). PGE publishes overnight/daily — a daytime-stuck Latest available interval near ~01:00 Pacific is expected.
- Config setup requires email, password, and account number; entry unique id is `pge_account_<id>`; new installs derive a stable opaque `account_key` from the account number (Energy statistic ids); entry removal clears that entry's external `pge_energy:*` statistics. Manual/alpha bearer-token mode is removed (legacy entries may still load until reauth).
- Usage history is dual-published: external `pge_energy:<account_key>_{consumption,return,cost,compensation,temperature}` plus mirrored entity statistics on `sensor.pge_*_{energy,return,cost,compensation,outdoor_temperature}`; outdoor `temperature` is a first-class synced series. Signed HOURLY `getUsageCompare` rows split via `usage_direction.split_signed_usage`: positive kWh/amount → `_consumption`/`_cost`, negative hourly kWh/amount → `_return`/`_compensation`; `usageStatus` stays `kWh-Delivered` (not directional). Coarse DAILY/MONTHLY net rows never invent gross return/compensation. Hourly tip sensors use `device_class=None` with `state_class=measurement` (HA rejects `energy`/`monetary` + `measurement`); lifetime energy/return keep `total_increasing` and cost/compensation keep `total` for the Energy dashboard. HA `import_statistics` always overwrites `state`/`sum` for an existing `(statistic_id, start)` — a persistent recorder mismatch means the write never landed (check DB health), not a benign adjust. Ack re-issues the write before failing; cost/return/compensation/temperature ack failures mark days failed instead of soft-failing the whole poll. Boot migration `signed_usage_split_migration_done` rewrites proven fine-grained negative consumption/cost into return/compensation.
- Monetary mean billing sensors (`account_balance`, `amount_due`, `last_payment_amount`, `ytd_program_savings`) are external-only: they use `state_class=None`, and HA's `STATE_CLASS_REMOVED_ISSUE` is driven by recorder metadata presence — mirrors must be removed **and** existing entity statistics cleared once (`billing_mirror_cleanup_done`).
- MONTHLY usage returns ~12 billing periods relative to the requested end (not absolute newest). Backfill must page monthly from yesterday through the gap so covering periods are included; mark days before the oldest returned period complete (pre-service / no PGE history). Explicit null HOURLY kWh samples keep their timestamp, skip energy/cost writes, preserve temperature when present, and validate as `complete_with_gap` so the day completes without looping DAILY/MONTHLY; never coerce missing energy to zero or erase retained recorder data. Tiered backfill (hourly → daily → monthly) runs as a background task with a progress-stall watchdog, hard-release for uncancellable hangs, generation-guarded cleanup, per-tier timeouts, and bounded store saves. Never call `hass.async_block_till_done()` from import/runtime paths — a scheduled poll holding `import_lock` plus a tracked backfill awaiting that lock is a deterministic deadlock. `CancelledError` and stall abort must call `fail_sync_job` so sync_status cannot remain stuck at backfilling.
- Billing/programs import (v0.2): same Apigee GraphQL via `billing_api.py` — `getAccountDetailList`, nested `AccountDetail.paymentHistory` (not charge-summary), programs status + best-effort detail ops; soft-fail `billing_sync` after usage poll; option `include_billing` (default on). Prefer AccountDetail encrypted account/premise/SA over `getAccountInfo` group defaults. Bill PDFs (v0.7): REST `pge-bill-api/pdf/bills` after structured billing when `download_bill_pdfs` + `include_billing`; files under `www/pge_energy/<account>/bills/` (`/local/…`); Store v2 `bill_pdf_index`; modules `bill_pdf.py`, `bill_pdf_models.py`, `bill_pdf_parser.py`, `bill_pdf_store.py`, `bill_pdf_sync.py`, `bill_pdf_statistics.py`. Open-cycle estimates (v0.5): `getEnergyTrackerData` …
- Custom panel (v0.4+): `panel.py` + `websocket.py` + buildless frontend (`pge-panel.js`, `charts.js`, `data.js`, `theme.js`); sidebar `/pge`; static `/pge_energy_frontend` + `/pge_energy_brand`; Configure → Panel domain Store `pge_energy.panel` (`panel_settings.py`); admin WS `pge_energy/accounts` and `pge_energy/sync/subscribe`; charts via `recorder/statistics_during_period` + vendored Apache ECharts (`frontend/vendor/echarts.min.js`). Key docs: `docs/ARCHITECTURE.md`, `docs/AUTH_DISCOVERY.md`, `docs/DATA_CONTRACT.md`, `README.md`, `SECURITY.md`, and `docs/HA_*`; forward-looking notes under `.cursor/docs`.
