## Learned User Preferences

- Prefer unattended Home Assistant operation via stored PGE email/password; no HITL bearer-token handoff and no MFA support (MFA accounts are unsupported). Treat portal access tokens as short-lived: re-login may be required nearly every sync interval, including mid-sync renewal.
- Auth/sync failures must soft-fail: keep last-known sensors and recorder history; never blank the panel or purge downloaded usage/billing because renew failed. Long-running backfill must self-heal on stall (progress watchdog / stuck-task recovery) so sync_status cannot stay backfilling indefinitely without a HA restart.
- Prefer Cursor Browser (`cursor-ide-browser`) for live HA UAT with repo-root `./start`/`./stop`; custom-component Python changes need a full HA process restart (config-entry reload is not enough). After every substantive code or frontend change, confirm the affected surface (usually `/pge`) reflects the change and data loads correctly—blank, stale shells, or unexpected `unavailable` count as failure and require `./stop` then `./start` plus hard-refresh before calling the work done. Panel Sync status must reach complete (no failed backfill days) before UAT is done. Plans should embed Browser UAT checkpoints at code-review points (verify at `/config/integrations/integration/pge_energy`) and use the `.cursor/.ralph` loop for continuity, stopping only for HITL UAT confirmation before marking complete.
- Prefer the continual-delivery plan under `.cursor/plans/` as the source of truth (`instruct.md` is legacy); do not edit `.cursor/plans/` unless explicitly asked.
- Prefer polling interval UI as a number plus a minutes/hours/days dropdown (default every 4 hours) plus a configurable Pacific sync clock that anchors the hour/day grid (default 12:00 AM → 12am/4am/8am/noon/4pm/8pm), with no static “minutes” suffix on the number field.
- Prefer credentials-only setup (email/password + account number per entry); source naming includes the account number (e.g. `PGE <accountnum>`); locally bundled PGE logo; options UI with password reveal; account number read-only after setup. Same login may own multiple entries with different account numbers. Prefer no personal account details hardcoded outside `.env` (which is intended to be removed); never commit secrets.
- Prefer tiered full-history sync into HA (hourly, then daily/monthly as available), with user-controllable sync frequency and history depth in settings, plus a manual force-sync path: a start modal that reuses saved sync settings, then a dedicated progress page (not just a popup) with real-time stats, ETA, and a progress bar.
- Prefer stock Home Assistant Energy (`/energy`) and native energy cards for consumption, cost, and PGE outdoor temperature; do not depend on third-party energy chart addons.
- Prefer a first-party sidebar panel at `/pge` titled **PGE**, pinned immediately under the built-in **Energy** item via each user's `sidebar.panelOrder`, as the single place for usage, billing, programs, and live sync — buildless ES module + vendored Apache ECharts; never `/energy/pge` (HA routes panels by the first path segment). Panel/chart colors must follow HA theme tokens (light/dark/custom) so text and series stay readable when themes change.
- Prefer panel “At a glance” KPIs and Usage/analytics charts that respect PGE overnight publication lag (~24h): closed days through yesterday only — never wall-clock “today”, tip/latest-hour samples, tip outdoor temperature, or incomplete/open periods. Include “Since statement” cost/kWh (statement end → yesterday); chart ranges end at Pacific midnight exclusive; Usage primary fast-select is `24h` / This cycle / Last cycle / 7 days / Month, with More… for `6h`/`12h`/`3mo`/`6mo`/`12mo`/YTD (default `24h`; short windows are last N hours of published data); keep unavailable presets visible but disabled; surface upstream PGE publication gaps between At a glance and Usage. Prefer a combined multi-series Usage chart with fuller bars; analytics layout is Weather vs usage full-width above side-by-side Cost intelligence, equal chart heights, and heatmap titles above the plot. Range accounting should scale with the selected window (including multi-year/decade histories) while keeping hourly detail available; hide metrics that are zero only from missing data; keep Range accounting and breakdown tables as separate collapsibles whose open/closed state persists across range changes and browser reloads (default collapsed); style Billing as always-expanded (no accordion) matching Range accounting table layout; omit a separate Table view control (redundant with Range accounting); keep the panel mobile/tablet friendly; charts should highlight both bars and line points on hover, with tasteful hover motion on graphs and KPI cards; chart tooltips/popups should show human-facing PGE values and readable dates (not internal calculated intermediates).
- Prefer billing/programs as structured dual-publish data on the same entry/device (sensors + binary sensors + mirrored statistics); bill PDFs deferred. Prefer status/conditions for HA automations via a hybrid alert surface: typed `pge_energy_alert` domain events plus summary entities (problem/alert/reauth/failed-days/auth-fail-count), with HA repairs for critical/actionable issues; no built-in notify service—user automations own notifications. v1 catalog is core ops (auth/sync/billing/new bill) plus account lifecycle (amount-due/due-date, program/autopay flips), not data-quality signals.
- Prefer documenting important code changes in the matching root docs and keeping `tasks.md` as the running done/follow-up checklist (see `.cursor/rules/document-and-track-tasks.mdc`). After substantive `custom_components/pge_energy` changes, bump `VERSION` with SemVer (PATCH/MINOR/MAJOR), keep `const.py` / `manifest.json` / frontend `?v=` / README in sync, then publish a matching GitHub Release (`vX.Y.Z` via `gh release create`) so HACS Latest updates (see `.cursor/rules/bump-version-on-code-changes.mdc`).

## Learned Workspace Facts

- This repo (`homeassistant-pge`) is a Home Assistant custom integration under `custom_components/pge_energy` (PGE Energy / Portland General Electric), prepped for public HACS distribution.
- Local live HA for browser UAT is started with repo-root `./start` (via `scripts/dev_ha_live_server.py`) at `http://127.0.0.1:8123`; stop with `./stop`; run dirs live under `outputs/ha_live/` (gitignored). On bare `./start` HA (no Supervisor), `homeassistant.restart` from the UI can kill the process without bringing it back—use `./stop` then `./start`.
- In-process harness is `scripts/dev_ha_harness.py` with outputs under `outputs/ha_harness/`; `.env` loading is opt-in via `env_loader` and must never auto-load in tests/CI.
- Shell commands in this workspace should use `exec /bin/bash -lc '...'` to avoid zsh wrapper exit-code noise.
- Auth path is Cognito + Apigee hybrid email/password (`portal_auth`); MFA and captcha challenges fail closed as unsupported.
- OptionsFlow exposes Configure → Sync settings and Update credentials; polling is `polling_interval` + `polling_interval_unit` + `sync_local_time` (default every 4 hours from 00:00 America/Los_Angeles). PGE publishes overnight/daily — a daytime-stuck Latest available interval near ~01:00 Pacific is expected.
- Config setup requires email, password, and account number; entry unique id is `pge_account_<id>`; manual/alpha bearer-token mode is removed (legacy entries may still load until reauth).
- Usage history is dual-published: external `pge_energy:<account_key>_{consumption,cost,temperature}` plus mirrored entity statistics on `sensor.pge_*_{energy,cost,outdoor_temperature}`; outdoor `temperature` is a first-class synced series. HA `import_statistics` always overwrites `state`/`sum` for an existing `(statistic_id, start)` — a persistent recorder mismatch means the write never landed (check DB health), not a benign adjust. Ack re-issues the write before failing; cost/temperature ack failures mark days failed instead of soft-failing the whole poll.
- Monetary mean billing sensors (`account_balance`, `amount_due`, `last_payment_amount`, `ytd_program_savings`) are external-only: they use `state_class=None`, and HA's `STATE_CLASS_REMOVED_ISSUE` is driven by recorder metadata presence — mirrors must be removed **and** existing entity statistics cleared once (`billing_mirror_cleanup_done`).
- MONTHLY usage returns ~12 billing periods relative to the requested end (not absolute newest). Backfill must page monthly from yesterday through the gap so covering periods are included; mark days before the oldest returned period complete (pre-service / no PGE history). Tiered backfill (hourly → daily → monthly) runs as a background task with a progress-stall watchdog, hard-release for uncancellable hangs, generation-guarded cleanup, per-tier timeouts, and bounded store saves. Never call `hass.async_block_till_done()` from import/runtime paths — a scheduled poll holding `import_lock` plus a tracked backfill awaiting that lock is a deterministic deadlock. `CancelledError` and stall abort must call `fail_sync_job` so sync_status cannot remain stuck at backfilling.
- Open-cycle estimates (v0.5): `getEnergyTrackerData` (`EnergyTrackerDataParams` = encrypted account + person id) backs the portal “Current Use” card — est. charges so far, billing cycle day N of M, est. next bill min/max. Fetched soft-fail in `billing_sync`, exposed as 5 sensors + panel “PGE est.” cards; PGE's own projection, so it does not reconcile with imported interval sums.
- Billing/programs import (v0.2): same Apigee GraphQL via `billing_api.py` — `getAccountDetailList`, nested `AccountDetail.paymentHistory` (not charge-summary), programs status + best-effort detail ops; soft-fail `billing_sync` after usage poll; option `include_billing` (default on). Prefer AccountDetail encrypted account/premise/SA over `getAccountInfo` group defaults. PDF deferred.
- Custom panel (v0.4): `panel.py` + `websocket.py` + buildless frontend (`pge-panel.js`, `charts.js`, `data.js`, `theme.js`); sidebar `/pge`; static `/pge_energy_frontend` + `/pge_energy_brand`; admin WS `pge_energy/accounts` and `pge_energy/sync/subscribe`; charts via `recorder/statistics_during_period` + vendored Apache ECharts (`frontend/vendor/echarts.min.js`). Key docs: `ARCHITECTURE.md`, `AUTH_DISCOVERY.md`, `DATA_CONTRACT.md`, `README.md`, `SECURITY.md`, `tasks.md`, and `docs/HA_*`; forward-looking notes under `.cursor/docs`.
